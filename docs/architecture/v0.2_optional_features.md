# v0.2 optional-feature evaluation

MADDENING v0.2 ships several optional surfaces a downstream project *may*
adopt. As the final step of the MIME v0.2 fit-up (§7), each was evaluated
against MIME's current needs.

**None is a v0.2 compatibility gap** — MIME is fully MADDENING-v0.2-compatible
without any of them — so all five are deferred. Each section below records the
concrete trigger for when adoption becomes worthwhile.

## Profiler — `/sim/profile` Perfetto export — *defer*

MADDENING's `maddening/core/simulation/profiler.py` exposes a clean API
(`profile_graph`, `profile_report_to_perfetto`, `JaxProfilerSession`).
Surfacing it through `runner/server.py`'s ZMQ REP socket would be a small,
well-scoped addition — but it is a *feature* on the runner, and the
`runner/server.py` redesign is a separately-tracked deferred follow-up.

**Adopt when** the runner is next reworked: add a `profile` REP command that
wraps `profile_graph` + `profile_report_to_perfetto`.

## `BinaryStateEncoder` — field subscriptions + zstd — *defer*

A streaming-bandwidth optimisation. The sweep HDF5 writer
(`data/hdf5_schema.py`) stores small scalar rows — h5py already chunks them —
and `viz/streaming_observer.py` shows no measured bandwidth pressure.

**Adopt when** streaming bandwidth is demonstrated to be a bottleneck.

## `GraphManager.validate_sharding()` — *defer (not applicable)*

§3 deliberately keeps the FVM and LBM nodes unsharded — their `halo_width()`
return blocks sharding — and MIME shards no graphs today, so the call has
nothing to validate.

**Adopt when** sharded graphs are introduced, as a guard inside a sharding
smoke test.

## Surrogate primitives — `maddening/surrogates/primitives/` — *defer (nothing to consume)*

The package currently contains only an empty `__init__.py`; there are no
primitives to consume. MIME's `surrogates/cholesky_mlp.py` stands alone
correctly.

**Adopt when** MADDENING populates the package — this intersects MADDENING's
own deferred "decoder-zoo pull-over from MIME" item.

## AWS / GCP cloud providers — *defer*

v0.2's `cloud/providers.py` adds `AWSProvider` / `LambdaLabsProvider`
credential handling alongside `RunPodProvider` — an available option, not a
compatibility gap. MIME's RunPod job specs work as-is.

With §5's resume facility (`ResumableSweep`) now in place, spot instances on
*any* provider are safe to use, so AWS/GCP spot is a viable **future cost
optimisation**.

**Adopt when** a run's economics justify switching a job spec to AWS/GCP spot.
